# 다음 작업 진행

1. `docs/TASKS.md`를 읽는다. `$ARGUMENTS`가 있으면 그 작업을, 없으면 체크되지 않은 첫 작업을 고른다.
2. 고른 작업이 `[사람]`만 표시돼 있으면, 사람이 할 일을 단계별로 안내하고 여기서 멈춘다. `[사람+Claude]`면 Claude 몫만 하고 사람 몫은 안내한다. 작업에 **선행 조건**이 적혀 있으면 가장 먼저 확인하고, 안 맞으면 무엇이 필요한지 안내한 뒤 멈춘다. 앞 작업이 체크되지 않았는데 그 결과물이 필요하면 역시 멈춘다.
3. 작업에 적힌 SPEC 장만 `docs/SPEC.md`에서 읽는다. 앞선 작업에서 만든 파일 중 필요한 것만 읽는다.
4. 바꿀 파일이 둘 이상이면 무엇을 어떻게 바꿀지 5줄 이내 계획을 먼저 보여준다.
5. 테스트를 먼저 쓰거나 함께 쓴다. 작업에 적힌 **완료 조건**을 그대로 테스트나 명령으로 옮긴다.
6. 관련 테스트만 먼저 돌리고, 통과하면 `npm run check`를 돌린다. 실패하면 원인을 고치고 다시 돌린다. 테스트를 지우거나 기대값을 코드에 맞춰 바꿔서 통과시키지 않는다.
7. 완료 조건의 명령 출력(마지막 몇 줄)을 증거로 보여준다.
8. `docs/TASKS.md`에서 그 작업을 체크하고, SPEC에 없던 결정이 있었으면 `docs/DECISIONS.md`에 한 줄 추가한다.
9. 바뀐 파일 목록과 커밋 메시지 제안(`<영역>: <내용>`)으로 끝낸다. 커밋은 사용자가 요청할 때만 한다.
